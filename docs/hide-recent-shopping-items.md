# Скрытие редких товаров из недавних

Статус: реализовано и развёрнуто 18 ноября 2026 в `feat/hide-recent-shopping-items`.

## Задача

Убирать редкие товары из раздела «Недавние» конкретного списка покупок. Товар остаётся в каталоге, история покупок не удаляется.

## Согласованное поведение

- Активная позиция списка сохраняет меню: «Отметить купленным», «Убрать из списка», «Редактировать».
- Нажатие на карточку недавнего товара по-прежнему добавляет его в список.
- Меню недавнего товара содержит «Добавить в список», «Убрать из недавних», «Редактировать».
- Скрытие относится к паре «список + товар», поэтому не скрывает товар из других списков. Это состояние общее для участников и клиентов.
- Каталог и история покупок остаются без изменений. Отмены скрытия нет; товар можно снова найти через поиск.
- После следующего обычного снятия позиции с этого списка (отметки покупки) товар снова становится недавним. Простое добавление или удаление без истории его не возвращает.
- Скрытая позиция не замещается более старой. При лимите 120 может отображаться 119 товаров. При необходимости проще фильтровать последние 120 записей после выборки, не подбирая старые записи взамен.
- Элемент управления скрытием доступен в Web. Старые мобильные приложения не меняются; они получают тот же формат списка с меньшим количеством недавних позиций при обновлении. На открытом клиенте задержка до очередного обновления может составить около 30 секунд.

## План реализации

1. Создать отдельное состояние скрытия для списка и товара; добавить миграцию БД.
2. Добавить авторизованный API-метод скрытия. Фильтровать скрытые позиции в `recentItems` ответа списка и в устаревшем endpoint недавних товаров, не меняя форму ответов и старые маршруты.
3. Снимать скрытие только при новой обычной отметке покупки; не снимать его при добавлении или жёстком удалении без записи истории.
4. Добавить русскую и английскую подписи, меню недавней карточки и новое Socket.IO событие для открытых Web-клиентов. Старые мобильные клиенты проигнорируют новое событие и увидят обновлённый ответ при следующем запросе списка.
5. Не менять меню активной позиции; нажатие карточки недавнего товара по-прежнему добавляет его в список.
6. Проверить API-тестами на изолированной БД: авторизацию, разные списки, сохранение истории, отсутствие замещения более старой позицией, повторное появление после новой покупки, Socket.IO доставку двум Web-клиентам и прежний формат ответов. Проверить Web-сценарий в браузере и совместимость с неизменёнными мобильными клиентами.
7. Собрать образы из этой ветки, сделать резервную копию продовых настроек и данных по runbook, развернуть, проверить health/API и сценарий на временных production fixtures, затем удалить все временные данные.
